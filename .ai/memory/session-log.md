## Session 1 - 2026-09-12 - orchestrator, staff_engineer

**Goal:** Scaffold the AI harness from AI-SCAFFOLD-1/2.md, then build a fully-functional POC
of the SEC WhatsApp AI counsellor for a management demo, on free/open-source infra.

**Outcome:** partial — application built, blocked before first run

**Did**
- Created the full `.ai/` harness tree, `AI-HARNESS.md`, and `CLAUDE.md` (`@AI-HARNESS.md
  @AGENTS.md` — the latter auto-generated by `next dev`'s tooling, kept alongside).
- Read the three source artifacts in `SEC Whatsapp/` (BRD v1.0, PRD v8.0, business case
  v13) to ground the build in the real spec rather than assumptions.
- Asked the user 4 scoping questions (WhatsApp channel, LLM provider, deploy access,
  database) via AskUserQuestion — answers recorded as ADR-002/003 and Q-000a-d.
- Scaffolded a Next.js 16 (App Router) + TypeScript + Tailwind project at the repo root.
- Designed `prisma/schema.prisma` covering every BRD entity (Asset, ClickRecord, Contact,
  ConsentLedgerEntry, Message, MessageTemplate, SendLog, EligibilityRequest, HandoffToken,
  Handover, AgentUser, TranscriptView, Ambassador, AmbassadorPayout, AlumniProfile,
  AlumniConnect, ResourceItem, GroundingLog, SemanticCacheEntry, PilotMetricSnapshot,
  CostLedgerEntry, ProcessioSyncLog, SystemConfig, LastTouchEvent).
- Built `lib/`: attribution (asset codes, click tokens, 4-tier resolution, first/last-touch),
  consent (append-only ledger, age gate, opt-out), config (DB-backed feature flags/caps),
  propensity scoring, eligibility (calls a mock DIY BRE, never computes credit logic
  itself), handoff (signed JWT deep links, Processio sync gate), send governor (the single
  choke point for every outbound send — window/template/cap/quality/spend enforcement),
  and the conversation engine: a deterministic `flow.ts` stage machine for
  consent/age-gate/journey-fork/profiling/eligibility/handoff, an Anthropic-based
  `orchestrator.ts` for free-text counselling turns (tool-use loop: `ground_with_google_
  search` + forced `submit_reply`), a Gemini-based `grounding.ts` (real Google Search
  grounding tool, sanitisation, semantic cache, always-ground allow-list), and a
  keyword-overlap `rag.ts` over a synthetic outcomes corpus.
- Built both channels: the real Meta webhook (`app/api/webhook/whatsapp`, signature
  verification, dedup, debounce) and the web chat mirror (`app/chat`, SSE-based, a
  WhatsApp-styled UI, zero external setup — doubles as the FR-J04/J05 requirement).
- Built the admin console (overview/pilot-metrics, assets+QR, funnel, payouts,
  costs, transcript review, settings) and agent console (thread list with filters,
  conversation view, governed send box, handover claim/resolve), plus simple
  signed-cookie auth and a seed script.
- Built `app/portal` — a DIY portal stub proving the OTP-skip handoff token flow, since
  DIY doesn't exist in this environment.

**Decided**
- ADR-001: Next.js + Prisma + Postgres, one Render service.
- ADR-002: Claude + Gemini replace Bedrock + Bedrock-hosted grounding; grounding stays a
  tool, never the conversation model.
- ADR-003: real Meta test number + web mirror, both wired to the same engine.
- ADR-004: deterministic state machine for compliance-sensitive layers; AI only for
  free-text counselling turns.
- ADR-005: pinned Prisma to 7.10.0 after discovering `prisma@latest` is an unrelated 8.0
  RC platform rewrite with no `generate`/`migrate` commands.

**Learned**
- `@google/generative-ai` is EOL (Aug 2025) — had to verify current `@google/genai` syntax
  via live web search rather than trust training data.
- Prisma's npm `latest` tag currently points at an 8.0.0-rc that is architecturally a
  different product (hosted "Prisma Developer Platform"), not an incremental CLI update —
  worth remembering this can happen with any fast-moving dependency, not just this one.
- Moving a `create-next-app` scaffold from a scratch temp dir into the repo root silently
  overwrote `CLAUDE.md` (Next.js's own tooling generates one pointing at its `AGENTS.md`) —
  caught via the system's "file changed on disk" notice, fixed by making CLAUDE.md import
  both files.

**Continued (same session) — deployment**
- User supplied a single Google API key ("use it for both grounding and non-grounding"),
  Render token, admin/password, then Meta WhatsApp test credentials, then a GitHub repo URL.
- Rewrote the orchestrator from Anthropic to Gemini function-calling (ADR-006); verified
  the exact request/response shapes (`functionDeclarations`, `response.functionCalls`,
  `Type.OBJECT/STRING/BOOLEAN`) against the installed `@google/genai` package's own `.d.ts`
  files rather than trusting web search summaries a second time.
- Pushed to `github.com/ayushgoswami-avanse/avanse-wa-bot` (public, `SEC Whatsapp/` source
  docs excluded via .gitignore — those are confidential Avanse business documents and must
  never be in a public repo).
- Created the Render Postgres DB and web service via the Render REST API directly (no
  GitHub App install needed — Render deploys from a public git URL with `autoDeploy` not
  actually working for that source type, so every push needs a manual `POST .../deploys`).
- Two build failures, both fixed from Render's build logs (not guessed in advance):
  Prisma 7 rejects `datasource.url` in schema.prisma (needs `prisma.config.ts` + a
  `@prisma/adapter-pg` driver adapter in `PrismaClient`), then several TypeScript errors
  (missing `@types/qrcode`/`@types/jsonwebtoken`, a `Journey` enum narrowing issue, and the
  hand-rolled tool-declaration type not matching `@google/genai`'s real types).
- **Deployed and live**, smoke-tested the entire golden path end-to-end via the web mirror
  API directly (curl): consent → age gate → journey fork → full international profiling →
  RAG hook fired → a real Gemini-grounded answer (current 2026 US F1 visa fee figures,
  correctly cited and dated) → Low-tier conversational college fallback → Tier 1
  eligibility via the mock BRE (real computed figure) → signed handoff token → `/portal`
  decoded it correctly → replay on the same token was correctly rejected.
- Discovered Avanse's corporate Zscaler proxy blocks `graph.facebook.com` entirely (this
  sandbox cannot make Meta Graph API calls directly) — built an admin-only route
  (`/api/admin/whatsapp-webhook-setup`, also a Settings-page button) that runs the WABA
  subscribe + webhook-override calls server-side on Render instead, since Render's network
  isn't behind that proxy.

**Left undone / next**

  subscribe the WABA now that the app is live, then get the user to send a real WhatsApp
  message from one of their 5 verified test numbers to confirm that channel end-to-end.
- Populate `.ai/product/brd.md` / `prd.md` with condensed content from the source docx —
  done earlier this session, already reflected in those files.

**Watch out for**
- Do not let a future `npm update` touch `prisma`/`@prisma/client` past 7.x without
  re-reading ADR-005 first.
- `sendOutboundMessage` in `lib/messaging/sendGovernor.ts` is the only permitted path to
  the Meta client — any new send feature must go through it (see tech-debt landmines).
- The web-mirror SSE greeting is deliberately triggered inside `/api/web-mirror/stream`,
  not `/start` — moving it back will silently drop the first message (race condition,
  documented in tech-debt.md).
